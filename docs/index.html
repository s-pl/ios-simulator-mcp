Controla el Simulador de iOS desde tu agente

ios-simulator-mcp es un servidor Model Context Protocol que da a Claude (o a cualquier cliente MCP) las manos y los ojos que necesita para trabajar con el Simulador de iOS: arrancar dispositivos, instalar y lanzar tu app, tocar la pantalla, leer lo que hay en ella, capturarla y simular el entorno.

Dispositivos

Listar, arrancar, apagar y restaurar simuladores.

Apps

Instalar, lanzar, terminar, abrir deep links e inspeccionar contenedores.

Interfaz

Leer el árbol de accesibilidad, tocar, deslizar y escribir.

Multimedia

Capturas de pantalla y grabación de vídeo.

Entorno

Ubicación, modo oscuro, barra de estado, permisos y push.

Logs

Logs del sistema filtrados por proceso o texto.

Solo macOS. El Simulador de iOS no existe en Windows ni en Linux. En esos sistemas el servidor arranca y publica sus herramientas, pero cada llamada devuelve [UNSUPPORTED_PLATFORM].

Instalación

1. Descarga y compila

git clone https://github.com/s-pl/ios-simulator-mcp.git
cd ios-simulator-mcp
npm install

npm install también compila el proyecto a dist/.

2. Regístralo en tu cliente MCP

Claude Code

claude mcp add ios-simulator -- node "$(pwd)/dist/index.js"

Comprueba que está conectado con claude mcp list o con /mcp dentro de una sesión.

Claude Desktop y otros clientes

Añade el servidor al archivo de configuración del cliente (en Claude Desktop, ~/Library/Application Support/Claude/claude_desktop_config.json):

{
  "mcpServers": {
    "ios-simulator": {
      "command": "node",
      "args": ["/ruta/absoluta/ios-simulator-mcp/dist/index.js"]
    }
  }
}

3. Instala idb opcional

simctl no puede inyectar toques ni leer la pantalla, así que las herramientas ui_* usan idb de Meta. El resto del servidor funciona sin él.

brew tap facebook/fb
brew trust facebook/fb      # solo si Homebrew rechaza el tap por no ser de confianza
brew install idb-companion
pipx install fb-idb

Si el cliente MCP no encuentra idb (las apps de escritorio no heredan el PATH de tu terminal), indica la ruta completa con IOS_SIMULATOR_MCP_IDB_PATH. La obtienes con which idb.

Primeros pasos

Con el servidor conectado, pídele al agente lo que quieras en lenguaje natural. Por ejemplo:

  • «Arranca un iPhone 16 y hazme una captura.»
  • «Instala build/MyApp.app, lánzala e inicia sesión con el usuario de pruebas.»
  • «Abre myapp://settings, ponlo en modo oscuro y dime si algo se ve mal.»
  • «Concede permiso de fotos a mi app y envíale una push de prueba.»
  • «Reproduce el fallo del carrito y enséñame los logs de MyApp del último minuto.»

El flujo habitual que seguirá el agente es:

  1. list_devicesencontrar el simulador
  2. boot_devicearrancarlo
  3. install_app / launch_appponer la app en marcha
  4. ui_describe_screenlocalizar elementos
  5. ui_tap / ui_type_textinteractuar
  6. screenshotverificar el resultado

Conceptos clave

El parámetro device

Casi todas las herramientas aceptan un device opcional, que puede ser un UDID o el nombre exacto del simulador (sin distinguir mayúsculas). Se resuelve así:

  • Omitido: se usa el único simulador arrancado. Si no hay ninguno o hay varios, se devuelve un error que indica cómo elegir.
  • UDID: ese dispositivo.
  • Nombre: ese dispositivo. Si varios runtimes comparten el nombre (p. ej. «iPhone 15» en iOS 17 y iOS 18), gana el que esté arrancado; si no se puede decidir, se pide el UDID.

Las operaciones donde adivinar sería peligroso (boot_device, erase_device) exigen device.

Puntos, no píxeles

Las herramientas ui_* trabajan en puntos, el espacio de coordenadas de UIKit. Una captura está en píxeles: puntos × escala del dispositivo (normalmente 3 en iPhone y 2 en iPad). Para tocar algo, lo fiable es usar el tapPoint que devuelve ui_describe_screen en vez de estimar coordenadas sobre la imagen.

Indicadores de comportamiento

Cada herramienta declara si solo lee, si modifica estado o si destruye datos. Los clientes MCP usan esa información para decidir cuándo pedir confirmación.

Arquitectura

El proyecto sigue una arquitectura hexagonal en cuatro capas. Las dependencias apuntan siempre hacia el dominio: el dominio no conoce a nadie y la capa MCP no sabe qué es simctl.

mcp/Presentación · ToolProviders, SimulatorMcpServer
↓ llama a
application/Casos de uso · servicios, DeviceResolver
↓ depende de
domain/Modelo, errores y puertos (interfaces …Gateway)
↑ implementa
infrastructure/Adaptadores · simctl, idb, SimulatorHost, CommandRunner
CapaResponsabilidadPiezas principales
domain/Modelo y contratos, sin dependencias externas.Device, Runtime, Point, SimulatorError, ports/*Gateway
application/Reglas de negocio y orquestación.DeviceResolver, DeviceService, AppService, UiService, MediaService, EnvironmentService, LogService
infrastructure/Hablar con el mundo real.NodeCommandRunner, SimulatorHost, Simctl*Gateway, IdbUiAutomationGateway
mcp/Exponer los casos de uso como herramientas MCP.ToolDefinition, *Tools, SimulatorMcpServer
container.tsComposition root: único lugar que conecta las capas.createContainer()

Recorrido de una llamada

  1. SimulatorMcpServer valida la entrada con el esquema zod de la herramienta.
  2. El ToolProvider la traduce a una llamada al servicio de aplicación.
  3. El servicio resuelve el dispositivo con DeviceResolver y aplica sus reglas.
  4. El gateway ejecuta el comando a través de SimulatorHost.
  5. Si algo falla, el SimulatorError vuelve al cliente como [CÓDIGO] mensaje.

Decisiones de diseño

  • Sin shell. Los comandos se lanzan como ejecutable más vector de argumentos, de modo que ningún valor enviado por el modelo puede inyectar comandos.
  • Un puerto por capacidad. idb es un adaptador más de UiAutomationGateway; puede sustituirse sin tocar la aplicación ni la capa MCP.
  • Herramientas declarativas. Cada herramienta es un ToolDefinition (contrato más execute) independiente del SDK; el servidor solo las registra y centraliza los errores.
  • Estado acotado. El único estado son las grabaciones en curso, encapsuladas en MediaService y liberadas al cerrar.
  • Operaciones destructivas explícitas. erase_device exige dispositivo y que esté apagado; nunca lo apaga por su cuenta.

Añadir una herramienta

  1. Si hace falta una capacidad nueva, añádela al puerto en src/domain/ports/ e impleméntala en su gateway.
  2. Expón el caso de uso en el servicio correspondiente de src/application/.
  3. Declara la herramienta en el ToolProvider de src/mcp/tools/:
defineTool({
  name: 'set_appearance',
  title: 'Set light or dark mode',
  description: 'Switches the simulator between light and dark appearance.',
  inputSchema: {
    appearance: z.enum(APPEARANCES).describe('Appearance to apply.'),
    device: deviceParam,
  },
  annotations: { ...Hints.mutating, idempotentHint: true },
  execute: async ({ appearance, device }) => {
    const target = await this.environment.setAppearance(appearance, device);
    return text(`${target.label} now uses the ${appearance} appearance.`);
  },
}),

Después ejecuta npm run docs:tools para regenerar la referencia de esta página.

Solución de problemas

Las herramientas ui_* responden EXECUTABLE_NOT_FOUND

Falta idb o el cliente no lo encuentra en su PATH. Instálalo y, si sigue fallando, define IOS_SIMULATOR_MCP_IDB_PATH con la salida de which idb.

NO_BOOTED_DEVICE al usar cualquier herramienta

No hay ningún simulador arrancado. Usa list_devices y luego boot_device, o pasa device.

Los toques caen en el sitio equivocado

Probablemente se están usando píxeles de la captura. Usa el tapPoint de ui_describe_screen, que ya está en puntos.

xcrun: error: unable to find utility "simctl"

Las herramientas de línea de comandos no apuntan a Xcode. Ejecuta sudo xcode-select -s /Applications/Xcode.app.

El vídeo grabado no se abre

La grabación solo se finaliza con stop_recording. Si el servidor se cierra de forma normal, detiene las grabaciones pendientes; si se mata el proceso, el archivo puede quedar incompleto.

¿Dónde veo qué comando falló?

Los errores COMMAND_FAILED incluyen la línea de comandos exacta y su salida. Puedes copiarla y ejecutarla en una terminal para reproducir el problema.

Si encuentras un fallo, abre una incidencia indicando la versión de Xcode y el mensaje de error completo.
